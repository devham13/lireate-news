# Исправления поисковой видимости от 22 ноября 2026 года

Область: запрет обхода контактов, две битые ссылки в трёх статьях,
обрезанные Title/H1 в трёх статьях и пропуски опубликованных страниц в sitemap.
Позиции в поиске этим скриптом не измеряются.

## Что меняется

- В `robots.txt` удаляется только точный `Disallow: /contacts` или `/contacts/`.
  Ограничения админки, документов и других путей сохраняются.
- В трёх строках `news` восстанавливаются полные `name` для H1 и отдельные
  законченные `seo_title`. Допустимы только прежнее подтверждённое значение
  или уже исправленное. Иная редакция сотрудника вызывает отказ от записи.
- В трёх статьях заменяются только `href` двух несуществующих адресов на
  проверенные действующие адреса того же материала или темы. Даты публикации,
  URL статей, содержание остальных ссылок и внешний контент сохраняются.
- В sitemap добавляются 66 проверенных адресов: 45 классов МКТУ, 13 инструментов,
  5 услуг, 2 страницы о компании и информационная страница о товарном знаке.
  Два исключённых варианта статей и старая страница продления не добавляются.
  Никакие новые 301 между похожими статьями не назначаются.
- Последующие генерации sitemap сохраняют новые адреса, удаляют повторы и не
  ставят всем услугам дату последней новости в качестве `lastmod`.
- Публикация использует отдельные H1 и SEO title. Утилита выбора SEO title
  больше не перезаписывает название статьи и не режет последнее слово.

## Доставка через существующий CRON

`scripts/lireate_hosting_cron.sh` запускает `lireate_visibility_maintenance.py`
до очереди новых статей. Достаточно синхронизации **lireate-news**, а не
`office-repo`. Запись разрешена только при уже установленном
`LIREATE_ALLOW_PUBLISH=yes` (также поддерживаются true, 1, on).

Скрипт загружает существующий `.env`, выбирает PHP через существующий
`pick_php_executable`, не печатает настройки подключения к БД. По умолчанию
прямой вызов — проверка без записи:

```bash
"$PY" "$REPO/scripts/lireate_visibility_maintenance.py" --env-file "$HOME/lireate-autopub/.env"
"$PY" "$REPO/scripts/lireate_visibility_maintenance.py" --env-file "$HOME/lireate-autopub/.env" --apply
```

Резервные копии: `$HOME/lireate-autopub/backups/visibility/<время>-<суффикс>/`.
`news.json` содержит до/после только шести затронутых строк и имеет права 0600.
В каталоге сохраняются исходные `robots.txt`, `sitemap.xml` и хеши файлов.
Каталог резервных копий и состояние обязаны находиться вне публичного DOCROOT.

Обновления БД используют сравнение прежних значений. Для InnoDB действует
транзакция; при ошибке на MyISAM выполняются обратные записи только там,
где значения всё ещё соответствуют изменениям скрипта. Файлы заменяются
атомарно с проверкой отсутствия параллельного изменения. При ошибке файлов
восстанавливаются файлы и затронутые записи CMS.

Успех: `STATUS: VISIBILITY_APPLIED`, затем при повторе
`STATUS: VISIBILITY_ALREADY_APPLIED`. Квитанция с версией конфигурации
сохраняется в `$HOME/lireate-autopub/state/seo-visibility-20261122-v1.json`.
Ошибка не блокирует обычную публикацию новостей, но остаётся в логе CRON.
Существующая подтверждённая настройка IndexNow используется для отправки
изменённых URL; принятие уведомления не подтверждает индексацию или рост позиций.

## Если локальные изменения мешают синхронизации хостинга

Не выполнять reset/clean и не перезаписывать рабочие файлы. Запустить проверенный
релиз из отдельного временного каталога в консоли хостинга:

```bash
set -euo pipefail
AUTOPUB="$HOME/lireate-autopub"
SOURCE="$AUTOPUB/repo"
PY="$(cat "$AUTOPUB/.python-interpreter")"
git -C "$SOURCE" fetch origin +refs/heads/main:refs/remotes/origin/main
RELEASE="$(mktemp -d "$AUTOPUB/seo-visibility.XXXXXX")"
git -C "$SOURCE" archive origin/main | tar -x -C "$RELEASE"
"$PY" "$RELEASE/scripts/lireate_visibility_maintenance.py" \
  --env-file "$AUTOPUB/.env" --apply
```

Это не меняет ветку или рабочие файлы существующего checkout.

## Проверка после применения

1. `/robots.txt` разрешает публичные контакты; ограничения других путей сохранены.
2. `/contacts/` и новые адреса sitemap отвечают 200 и имеют ожидаемый canonical.
3. Три статьи имеют законченные Title и полные H1, без искусственного многоточия.
4. На трёх страницах-донорах отсутствуют два старых `href`, новые цели отвечают 200.
5. В sitemap есть классы 1–45 и инструменты; нет добавленных алиасов и повторов.
6. Фактические позиции измеряются отдельно для Москвы, Казани и Санкт-Петербурга,
   для каждой поисковой системы и устройства. Обход и уведомление IndexNow
   не являются подтверждением попадания в ТОП.
